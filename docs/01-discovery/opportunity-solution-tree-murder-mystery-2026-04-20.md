## Desired Outcome

**Primary:** 세션 내 역할 몰입 극대화 + 플랫폼 반복 사용

| 지표                                                    | 측정 방식                | 판정 가설                           |
| ------------------------------------------------------- | ------------------------ | ----------------------------------- |
| **세션 완주율** (입문자 포함 그룹 별도 집계)            | 추리 종료 도달 여부      | 가정 #2 (입문자 장벽)               |
| **룰·도움말 조회 이벤트 횟수**                          | 인앱 탭 이벤트 카운트    | 가정 #6 (메타 부담 자동화 효과)     |

| **플랫폼 재플레이율** (4주 내 **다른 시나리오** 플레이) | 사용자×시나리오 매트릭스 | 콘텐츠 전략(자체 제작 + UGC) 유효성 |

**지표 설계 원칙:**

- 머더 미스터리는 범인 공개 후 동일 시나리오 재플레이 불가 → 재플레이율은 **다른 시나리오로의 이동** 기준
- 눈맞춤·연기 톤 같은 카메라 의존 지표는 프라이버시·UX 부담으로 제외
- 스마트폰 활성 시간은 BYOD 구조상 항상 ~100% 근처 → 신호 아님, 제외
- 캐릭터 발화 vs 메타 발화 비율은 음성 인식 + 발화 분류 ML 필요 → MVP 범위 밖, 제외
- 3초 몰입 펄스 탭은 "측정 행위가 몰입을 깬다"는 역설로 제외

## Opportunity Map

### Opportunity 1 (SELECTED): 입문자 역할 몰입 미경험

**문제:** 머더 미스터리 완전 입문자는 "역할 몰입이라는 재미" 자체를 경험해본 적 없음. 규칙과 씨름하다 게임이 끝남.

**근거 (캔버스):** Phase 2 "소외된 목소리" — 업계 어느 누구도 이들을 타깃으로 설계하지 않음.

**움직일 지표:** 입문자 포함 그룹 완주율, 디브리프 몰입 점수

**Solutions:**

1. 게임 시작 전 "역할 예열(Warm-up)" 단계
2. 상황 맞춤 "캐릭터 귓속말" 프롬프트
3. 입문자 전용 "첫 사건" 시나리오 ✅ **SELECTED**

---

### Opportunity 2: 메타 부담 주의력 분산

**문제:** 규칙·카드·힌트·진행 순서가 순차 수동 공유라 흐름이 끊김. "룰이 뭐였지?" 발화로 몰입이 깨짐.

**근거 (캔버스):** Phase 1 증상 — 규칙 장벽, 대기 비용, 중간 혼선.

**움직일 지표:** 룰·도움말 조회 횟수, 완주율

**Solutions:**

#### Solution 2A: 진행 자동 스크립트 엔진

- **무엇:** 씬 전환·타이머·단서 배포를 플랫폼이 자동 진행. 대화 공백·시간·트리거 도달 시 다음 씬으로 자연 전환. 플레이어는 "다음 단계" 버튼을 의식할 필요 없음.
- **가설:** GM·호스트의 수동 진행 순간 자체가 극의 흐름을 끊는다. 자동화되면 그룹은 연속된 극 안에 머무를 수 있다.
- **실험:** 씬 3개짜리 짧은 시나리오로 자동 엔진 on/off 비교 (각 10팀). 관찰자 기록 메타 발화 빈도 + 디브리프 몰입 점수.
- **리스크:** 타이밍 파라미터가 틀리면 역으로 몰입 파괴. 튜닝 구간 필요.

#### Solution 2B: Just-in-Time 규칙 공개

- **무엇:** 사전 룰북 설명 없음. 상황이 발생하는 순간에만 해당 플레이어 폰에 짧게 표시 ("알리바이 단계 시작 — 본인 위치를 말해보세요. 힌트 공유 가능"). 룰 학습을 씬 속으로 분산.
- **가설:** 룰 설명 구간 자체가 이탈 트리거. 필요할 때만 공개하면 학습 부담이 분산되어 룰·도움말 조회 횟수가 급감한다.
- **실험:** JIT on vs 사전 룰북 제공 off로 입문자 포함 그룹 20팀 비교. 룰·도움말 조회 이벤트 횟수 비교.
- **시너지:** Opp 1(입문자 장벽)과 강한 교차. Solution 3(입문자 시나리오)과 **번들 가능**.

#### Solution 2C: 힌트 자동 드립(Drip) 타이밍

- **무엇:** 씬·시간·플레이어 행동에 따라 힌트를 플랫폼이 자동 공개. "지금 힌트 줘야 하나?" 판단 없음. 전원이 플레이어로 참여.
- **가설:** 힌트 수동 공급이 한 사람을 진행자 역할로 자연 흡수시킴. 자동화하면 GM 배역이 사라지고 전원 캐릭터 몰입 가능.
- **실험:** 자동 드립 on 상태로 6팀 운영 → 기존 GM 주도 오프라인 세션과 디브리프 비교. 특히 평소 GM 역할자의 몰입 점수 추적.
- **이슈:** 드립 타이밍 메타데이터 작성 공수 큼. 시나리오당 추가 제작 비용 발생.

### Opportunity 3: 즉시성·접근성 장벽

**문제:** 친구 3-6명이 이미 모였고 시간도 있는데, 물리 게임팩 없음 / 보드게임장 예약 실패 / 당일 결심 불가로 지금 시작할 수가 없음. 포기 또는 게임장 이동.

**근거 (캔버스):** Phase 2 결과 "포기 또는 보드게임장 이동"; 현상 유지 수혜자가 공간+진행+IP 번들 독점.

**움직일 지표:** 세션 완주율(첫 세션 도달), 재플레이율

**Solutions:**

#### Solution 3A: 원터치 시작 (QR 공유 + 게스트 합류)

- **무엇:** 호스트 1명이 시나리오 선택 → QR 코드 생성 → 다른 플레이어 스캔으로 자동 합류 (회원가입 없이 게스트 모드, 닉네임만). 모인 순간부터 3분 내 게임 시작.
- **가설:** "모였다 → 게임 시작" 사이의 마찰(계정 생성·친구 추가·링크 전달)이 큰 포기 원인. 마찰 제거로 첫 세션 도달률이 급상승한다.
- **실험:** QR 방식 MVP 제작 → 10팀에게 "지금 친구들과 시작해보세요" 미션 부여. 모인 시점부터 첫 씬 도달까지 시간 + 완주율.

#### Solution 3B: Pay-per-Play 단일 시나리오 저가 결제

- **무엇:** 구독 아닌 "시나리오 1편 = 1회 결제" (예: 8천원/그룹). 그룹당 1인이 결제, 나머지 무료 합류. 카페 1/3–1/4 수준 심리 장벽.
- **가설:** 구독·회원가입·가격 마찰이 "당일 결심"을 막음. 1회성 저가 모델이 "한 번 해볼까" 결정을 쉽게 만든다.
- **실험:** 결제 UX 프로토타입 + 랜딩페이지 A/B 테스트. 결제 완료율 + 결제 후 세션 시작률 비교.

#### Solution 3C: 모이기 전 시나리오 추천 + 합의 완료 상태

- **무엇:** 모임 예정 단계에서 "오늘 저녁 모일 예정 → 인원 5명, 난이도 초급, 분위기 코믹 → 추천 시나리오 3개". 모이기 전 콘텐츠 선택 완료. 모이는 순간 즉시 시작.
- **가설:** "뭘 할지 고르는" 시간이 즉시성의 숨은 적. 모임 전 결정되어 있으면 모임 순간부터 몰입 모드로 즉시 진입 가능.
- **실험:** 추천 + 사전 합의 플로우 on vs off. 모인 뒤 게임 시작까지 걸린 시간 측정.

## Selected POC

**Opportunity:** Opp 1 — 입문자 역할 몰입 미경험
**Solution:** Solution 3 — 입문자 전용 "첫 사건" 시나리오

**무엇:** 자체 제작 시나리오 중 1–2편을 **입문자 친화 설계**로 제작

- 캐릭터 3–4명 (많지 않음)
- 단순한 동기 구조
- 캐릭터 카드에 **말투·자세 가이드 2–3줄 포함** (예: "허세 많고 말이 빠름. 위기엔 농담으로 회피")
- 복잡한 트릭 대신 감정 드라마 중심

**Hypothesis:**

> 입문자의 장벽은 "규칙"이 아니라 **"내 캐릭터를 어떻게 연기해야 할지 모름"**이다. 캐릭터 수가 적고 말투 가이드가 담긴 카드로 설계된 시나리오라면, 입문자 포함 그룹의 완주율이 경험자 그룹 완주율의 80% 이상에 도달하고, 디브리프 몰입 점수가 3.5/5 이상을 기록한다.

**Scoring:**

| 기준        | 점수      | 근거                                                                                                           |
| ----------- | --------- | -------------------------------------------------------------------------------------------------------------- |
| Feasibility | 2/5       | 시나리오 1편 풀 제작은 수 주–수 개월. 어차피 제작할 것의 "첫 번째"를 입문자용으로 할 뿐이라 순증 비용은 제한적 |
| Impact      | 5/5       | 입문자 완주율·몰입 점수를 직접 움직임. 소외된 목소리(가장 큰 미개척 시장)를 정면 조준                          |
| Market Fit  | 5/5       | 업계에서 누구도 입문자용으로 설계하지 않음. 시장 공백 명확                                                     |
| **Total**   | **12/15** |                                                                                                                |

**왜 이 POC인가:**

- 확정된 콘텐츠 전략("자체 제작 시나리오로 품질 기준 확보")과 일관
- 입문자 완주율이라는 단일 지표가 가정 #2를 직접 판정
- 재플레이율(다른 시나리오 이동)로 플랫폼 반복 사용 가설도 동시 검증

## Experiment Plan — 2단계 순차

### Stage 1: 컨시어지 테스트 _(제작 전 저비용 검증)_

- **기간:** 2–3주
- **방식:** 기존 오프라인 시나리오를 **수기로 입문자 친화 버전**으로 개조 → 대면 세션으로 2–3팀 운영
  - 캐릭터 카드에 말투 가이드 2–3줄 추가
  - 캐릭터 3–4명으로 축소
  - 연구자 직접 배석
- **참가자:** 입문자 포함 그룹 2–3팀
- **측정:**
  - 입문자가 첫 발화를 몇 분 내 시작하는가 (관찰 기록)
  - 디브리프: "캐릭터가 돼본 것 같았다" 4/5 이상
  - 메타 질문("이 카드 뭐야?" "지금 누구 차례야?") 빈도 관찰
- **Go/No-Go 기준:**
  - 2/3 이상 팀에서 몰입 시그널 확인 → Stage 2
  - 시그널 미확인 → Solution 1(역할 예열) 또는 Solution 2(귓속말)로 피벗

### Stage 2: 소프트 런칭 _(Go 시 제품화)_

- **기간:** 4–8주
- **방식:** Stage 1 학습 반영해 입문자 전용 시나리오 1편 풀 제작 → 플랫폼 출시
- **참가자:** 입문자 포함 그룹 30–50팀
- **측정 지표:**
  - 완주율 (입문자 포함 그룹 vs 경험자 그룹)
  - 룰·도움말 조회 이벤트 횟수
  - 디브리프 몰입 점수 + **원인 귀속 질문** (아래 참조)
  - 4주 내 재플레이율 (다른 시나리오로 이동)
- **성공 기준:**
  - 입문자 포함 그룹 완주율 ≥ 경험자 그룹의 80%
  - 디브리프 몰입 점수 평균 ≥ 3.5/5
  - 4주 내 재플레이율 ≥ 30%
- **초기 5–10팀은 연구자 배석 관찰** (텔레메트리 해석 기준 보정)

## 실험 설계 주의점

**교란 변수 — 콘텐츠 품질 vs 플랫폼 자동화:**
입문자 전용 시나리오 1편만 내면 "스토리가 좋아서 완주했나, 플랫폼이 메타 부담을 풀어줘서 몰입했나"를 분리할 수 없음. 가정 #6 판정이 흐려짐.

**대응 — 디브리프 원인 귀속 질문 (복수 선택):**

> 이 세션을 완주하고 재밌었던 이유는? (해당되는 것 모두 선택)
>
> 1. 스토리가 재밌어서
> 2. 진행이 자동이라 룰에 덜 신경써도 돼서
> 3. 내 캐릭터를 연기할 만했어서
> 4. 친구들과의 분위기가 좋아서
> 5. 기타 (자유 기술)

응답 분포로 "콘텐츠 효과"와 "플랫폼 효과"를 정성 분리.

| 2C 힌트 자동 드립     | 2/5         | 4/5    | 3/5        | **9/15**  | 업계 전제 뒤집기(GM 제거) 가치 있으나 시나리오당 제작 공수 큼           |

**강한 대체 POC: 2B (JIT 규칙 공개).** 현재 POC와 번들 가능 — "입문자 시나리오 + 룰 사전 설명 없음"이 하나의 실험으로 묶임.

**강한 대체 POC: 3A (QR 원터치 시작).** 현재 POC(Solution 3)가 "시나리오로 몰입을 푼다"는 **콘텐츠 베팅**인 반면, 3A는 "첫 세션 도달 자체가 바닥"이라는 **UX 베팅**. 두 베팅은 보완적 — 병렬 실험 가능.
