- **플레이어:** 호스트·게스트 구분 없이 세션에 참여 중인 모두

## Epic 1 — 시나리오 진행 엔진 (런타임 상태 기계)

PRD §7.2 Epic 1 책임 매핑. 상태 변화·ACL·브로드캐스트·메타 파싱이 본 Epic에 귀속.

### User Story E1-01

- **Summary:** 호스트가 회원가입 없이 시나리오를 골라 초대 번호를 띄운다

#### Use Case

- **As a** 호스트
- **I want to** 앱을 열자마자 시나리오를 고르고 초대 번호를 띄우고
- **so that** 친구들이 모인 그 자리에서 회원가입 마찰 없이 5분 안에 단계 1로 들어갈 수 있다

#### Acceptance Criteria

- **Scenario:** 호스트가 첫 진입에서 시나리오 카탈로그를 거쳐 초대 번호를 생성
- **Given:** 호스트가 앱을 처음 연다
- **and Given:** 회원가입·로그인 단계가 노출되지 않는다
- **and Given:** 카탈로그에 최소 1편의 시나리오가 노출된다
- **When:** 시나리오를 선택하고 "세션 시작"을 탭한다
- **Then:** 6자리 숫자 초대 번호가 호스트 화면에 표시되고 게스트 합류 대기 상태로 전환된다

---

### User Story E1-02

- **Summary:** 게스트가 닉네임만으로 세션에 합류한다

#### Use Case

- **As a** 게스트
- **I want to** 호스트가 불러주는 6자리 번호와 닉네임만 입력해 세션에 합류하고
- **so that** 회원가입·로그인을 거치지 않고 바로 캐릭터 배정 화면을 받을 수 있다

#### Acceptance Criteria

- **Scenario:** 게스트가 초대 번호로 합류
- **Given:** 호스트가 합류 대기 상태에 있다
- **and Given:** 게스트가 유효한 6자리 초대 번호를 알고 있다
- **and Given:** 게스트는 어떤 가입·인증 화면도 거치지 않는다
- **When:** 초대 번호와 닉네임을 입력하고 "합류"를 탭한다
- **Then:** 게스트 단말은 합류 확정 피드백과 함께 합류 대기 화면으로 전환되고, 호스트 화면 합류자 목록에도 해당 닉네임이 즉시 추가된다

### User Story E1-03

- **Summary:** 호스트가 인원을 확정하면 모두가 단계 1(도입)로 동시 전환된다

#### Use Case

- **As a** 호스트
- **I want to** 합류 인원이 확정된 시점에 "시작"을 탭해 모두를 단계 1로 보내고
- **so that** 진행자 1인이 화면을 일일이 안내하지 않아도 전원이 같은 페이즈에 정렬된다

#### Acceptance Criteria

- **Scenario:** 호스트의 시작 탭이 모든 합류자 단말을 단계 1로 동기 전환
- **Given:** 합류자 수가 시나리오 캐릭터 수와 정확히 일치한다
- **and Given:** 모든 합류자 단말이 합류 대기 화면을 보고 있다
- **When:** 호스트가 "시작"을 탭한다
- **Then:** 모든 단말이 단계 1(도입) 텍스트/오디오 자동 재생 화면으로 전환되며, 인원 불일치 상태에서는 "시작" 컨트롤이 비활성화되어 탭 자체가 발생하지 않는다

### User Story E1-04

- **Summary:** 캐릭터가 자동 배정되고 개인 정보가 본인에게만 도착한다

#### Use Case

- **As a** 플레이어
- **I want to** 단계 2에서 내 캐릭터와 비밀·동기 같은 개인 정보를 내 화면에서만 받고
- **so that** 옆 사람의 화면을 훔쳐보지 않으면 내 비밀이 보호된다는 걸 신뢰하고 몰입할 수 있다

#### Acceptance Criteria

- **Scenario:** 단계 2에서 캐릭터 자동 배정 + 개인 정보 1대1 전달
- **Given:** 단계 1이 끝났다
- **and Given:** 합류 인원 = 시나리오 캐릭터 수
- **When:** 엔진이 단계 2로 전환한다
- **Then:** 각 플레이어 단말의 본인 카드에 모든 필드(이름·직업·배경·동기·알리바이·비밀·관계 + 시나리오 저자 커스텀 필드)가 노출되고, 다른 캐릭터의 어떤 필드도 자동 동기되어 노출되지 않는다 (이름·직업처럼 공개되어야 할 정보는 시나리오 저자가 단계 1 도입 텍스트나 단계 2 캐릭터 소개 멘트로 직접 풀어 쓴다)

### User Story E1-04b

- **Summary:** 단계 3 규칙 공지가 인앱 튜토리얼로 대체된다

#### Use Case

- **As a** 플레이어
- **I want to** 단계 3에서 규칙을 호스트 1인의 낭독으로 듣는 대신 내 단말의 인앱 튜토리얼로 받고
- **so that** "지금 뭘 해도 되는지"를 다른 사람에게 묻지 않고 진행할 수 있고, 규칙 미숙지로 인한 초반 이탈을 줄인다

#### Acceptance Criteria

- **Scenario:** 단계 3 인앱 튜토리얼 (고정 문구) + 모든 합류자 통과 시 L1 전환
- **Given:** 단계 2가 종료되었다
- **When:** 엔진이 단계 3에 진입한다
- **Then:** 각 플레이어 단말에 인앱 튜토리얼이 1회 표시되어 거짓말 허용 범위(MVP 단일 정책 `all_players` — *"전원 거짓말 가능"*)와 기본 진행 규칙이 플랫폼 고정 문구로 안내되고, 각자 "확인" 탭으로 본인의 통과 상태를 표시하며, 모든 합류자가 통과를 표시한 시점에 엔진이 L1으로 자동 전환된다 (이후 페이즈의 JIT 맥락 힌트·정책 enum 분기는 MVP 밖)

### User Story E1-05

- **Summary:** 라운드 시작 시 라운드별 프롬프트와 타이머가 자동으로 켜진다

#### Use Case

- **As a** 플레이어
- **I want to** 새 라운드가 시작될 때 "이번 라운드는 무엇을 하는 시간인지"를 화면에서 받고
- **so that** 진행자에게 "지금 뭐 하는 거야?"를 묻지 않아도 즉시 대화에 들어갈 수 있다

#### Acceptance Criteria

- **Scenario:** 루프 라운드 진입 시 프롬프트 + 타이머 자동 노출
- **Given:** 시나리오 메타가 총 라운드 수 N(MVP는 고정 횟수)과 각 라운드별 프롬프트·제한 시간을 선언한다
- **and Given:** 직전 라운드가 종료되었거나 단계 3이 종료되어 루프 첫 진입 시점이다
- **When:** 엔진이 라운드 k(1 ≤ k ≤ N)로 진입한다
- **Then:** 모든 단말에 라운드 k 프롬프트 + 카운트다운 타이머가 동시에 표시되고 시간 경고 임계점에서 시각/햅틱 알림이 울린다

### User Story E1-06

- **Summary:** 시나리오가 허용한 경우에만 1:1 밀담을 신청·진행·종료할 수 있다

#### Use Case

- **As a** 플레이어
- **I want to** 시나리오가 밀담을 허용할 때 다른 플레이어 1명에게 밀담을 신청하고 수락하면 둘만 "밀담 중" 상태로 들어가고
- **so that** 누가 누구와 이야기 중인지가 외부에 노출된 상태에서도 전략적 동맹·정보 교환의 사적 채널을 가질 수 있다

#### Acceptance Criteria

- **Scenario:** 밀담 상태 기계 — 1:1 한정, 한 라운드에 한 쌍만 동시 진행, 허용 시나리오에서만, 자발 종료·라운드 경계 자동 종료
- **Given:** 시나리오 메타에 `allow_private_talk: true`가 선언되어 있다
- **and Given:** 현재 페이즈가 L1(알리바이·심문·변론)이다
- **and Given:** 현재 진행 중인 밀담이 없다
- **When:** A가 다른 1명(B)에게 밀담을 신청하고 B가 수락 또는 거절한다
- **Then:** 다른 쌍이 이미 진행 중이면 신청 컨트롤이 전원 비활성화되어 신청 자체가 발생하지 않고, B가 수락하면 A·B 두 명만으로 밀담이 성립해 참여자 단말이 "밀담 중" 상태로 전환되며 (이때 나머지 플레이어의 신청 컨트롤은 자동 비활성화), B가 거절하면 밀담은 불성립으로 자동 소멸하고, 성립한 밀담은 참여자 자발 종료·라운드 경계 도달 시 자동 종료되어 다음 신청이 가능해진다 (다인 밀담·동시 다중 1:1 밀담·라운드별 신청 횟수 한도는 MVP 밖)

### User Story E1-07

- **Summary:** 두 플레이어가 아이템을 1:1 교환하면 양측이 두 아이템에 모두 접근권을 얻는다

#### Use Case

- **As a** 플레이어
- **I want to** 내 단서 카드를 다른 플레이어의 단서 카드와 맞바꾸고
- **so that** 소유는 옮기되 "어차피 봤던 단서"는 내 기억 부담 없이 계속 열람할 수 있다

#### Acceptance Criteria

- **Scenario:** 아이템 교환(exchange) — 1:1 단일 쌍
- **Given:** A는 아이템 X를, B는 아이템 Y를 소유한다
- **When:** A·B가 X↔Y 교환을 합의 확정한다
- **Then:** 소유권은 X→B, Y→A로 이동하고 A·B 모두 X·Y 두 아이템에 대한 접근권을 영구 보유하며 (양측이 사전에 일부 또는 전부의 접근권을 이미 갖고 있었는지 여부와 무관), 전원 공개 배너에 "라운드 N: A ↔ B (교환)"이 양방향 화살표로 라운드 꼬리표와 함께 전원 단말에 게시된다

### User Story E1-08

- **Summary:** 단서 소유자가 단서를 전원에게 공개한다

#### Use Case

- **As a** 플레이어
- **I want to** 내가 가진 단서를 전체에게 공개하고
- **so that** 모두가 같은 정보를 본 상태에서 추리 토론을 할 수 있다

#### Acceptance Criteria

- **Scenario:** 아이템 전체 공유(share_all)
- **Given:** A가 아이템 X를 소유한다
- **When:** A가 X에 대해 "전체 공유"를 확정한다
- **Then:** X의 소유권은 A에 그대로 유지되고 모든 플레이어에게 X 접근권이 부여되며, 전원 공개 배너에 "라운드 N: A → 전원 (전체 공유)"가 전원 단말에 게시된다

### User Story E1-09

- **Summary:** 단서 소유자가 지정한 N명에게만 단서를 공개한다

#### Use Case

- **As a** 플레이어
- **I want to** 내 단서를 내가 고른 일부 플레이어에게만 공개하고
- **so that** 동맹·역할극 흐름을 깨지 않으면서 정보를 전략적으로 분배할 수 있다

#### Acceptance Criteria

- **Scenario:** 아이템 부분 공유(share_partial) — N명 지정
- **Given:** A가 아이템 X를 소유한다
- **and Given:** A가 1명 이상의 다른 플레이어를 공유 대상으로 지정한다
- **When:** A가 X 부분 공유를 확정한다
- **Then:** X의 소유권은 A 유지, 지정된 수신자들에게만 접근권이 부여되고 비대상자 화면에는 X의 내용이 보이지 않으며, 전원 공개 배너에 "라운드 N: A → 영희, 철수, … (부분 공유)" 형태로 모든 수신자 닉네임이 명시되어 전원 단말에 게시된다

### User Story E1-10

- **Summary:** 라운드 진입 시 각자에게 조사할 가상 장소가 배정되고 그 장소의 단서가 도착한다

#### Use Case

- **As a** 플레이어
- **I want to** 새 라운드가 시작될 때 "이번 라운드 당신이 조사할 장소"를 카드로 받고 그 장소의 단서가 내 단말에 도착하고
- **so that** 알리바이 발화에 가상 공간 앵커가 생기고, 전원이 동시에 같은 장소를 본다는 마찰 없이 각자 다른 장소를 조사할 수 있다

#### Acceptance Criteria

- **Scenario:** L2 라운드 진입 — 조사 장소 카드 + 단서 ACL 부여
- **Given:** 시나리오 메타가 캐릭터 × 라운드 매트릭스로 `assigned_location_id`를 선언한다
- **and Given:** 해당 장소에 `origin_location_id`가 매핑된 아이템이 존재한다
- **When:** 엔진이 라운드 N의 L2 단계에 진입한다
- **Then:** 각 플레이어 단말에 "이번 라운드 조사 장소: [아이콘 + 이름 + 1줄 분위기]" 카드가 표시되고, 그 장소의 단서가 해당 플레이어에게 도착한다 (= 기존 Item ACL 메커니즘 그대로 재사용, 새 ACL 규칙 도입 없음)

### User Story E1-11

- **Summary:** 라운드 누적 단서가 사라지지 않는다

#### Use Case

- **As a** 플레이어
- **I want to** 이전 라운드에서 봤던 단서를 새 라운드에서도 계속 열람하고
- **so that** "그 카드 뭐였더라?"를 다른 사람에게 묻지 않고 추리 흐름을 끊김 없이 유지할 수 있다

#### Acceptance Criteria

- **Scenario:** 단서 monotonic 누적
- **Given:** 라운드 N에서 플레이어 A가 단서 X 접근권을 부여받았다
- **When:** 라운드 N+1로 진입한다
- **Then:** A의 단말에서 단서 X는 여전히 열람 가능하며 어떤 라운드 종료 이벤트도 X의 접근권을 회수하지 않는다

### User Story E1-12

- **Summary:** 단계 8에서 투표가 자동 집계되고 동점이면 호스트가 재투표를 결정한다

#### Use Case

- **As a** 플레이어
- **I want to** 투표 집계를 앱이 알아서 굴려 주고
- **so that** 누구도 종이·계산기 역할을 떠안지 않고 모두가 플레이어로 남는다

#### Acceptance Criteria

## Epic 2 — 캐릭터 카드 UI + 시각화

PRD §7.2 Epic 2 책임 매핑. Epic 1이 발생시킨 상태·메타·이벤트의 모든 표면이 본 Epic에 귀속.

---

### User Story E2-01

- **Summary:** 캐릭터 카드 한 번의 탭으로 핵심 정보에 도달한다

#### Use Case

- **As a** 플레이어
- **I want to** 어떤 화면에서든 한 번의 탭으로 내 캐릭터 카드를 열어 이름·배경·동기·알리바이·비밀·관계·말투 가이드를 보고
- **so that** "내 캐릭터가 뭐였더라"를 떠올리는 데 멘탈을 쓰지 않고 곧장 대화에 복귀할 수 있다

#### Acceptance Criteria

- **Scenario:** 카드 단일 탭 도달 — 말투·라운드 목표·미션·아이템·알리바이 장소 동거
- **Given:** 플레이어가 게임 진행 중인 어떤 페이즈에 있다
- **and Given:** 시나리오 저자가 본 캐릭터에 말투 가이드를 작성했다 (선택 필드 — 미작성 시 카드 상단 영역은 비표시)
- **When:** 플레이어가 카드 진입 컨트롤을 1회 탭한다
- **Then:** 단일 카드 표면에서 이름·배경·동기·알리바이·비밀·관계 본문 + 말투 가이드(상단 상시) + 현재 라운드 목표 영역(E2-02) + 미션 영역(E2-03, 단계 9-B 이전엔 자리표시자) + 아이템 섹션(E2-04, 소유/접근권 분리) + 내 알리바이 장소 라벨(E2-05) 모두에 추가 탭 없이 도달 가능하고, 모든 필드는 본인 단말에만 노출된다 (다른 캐릭터의 카드·필드를 조망하는 화면은 MVP 밖 — 공개되어야 할 정보는 단계 1 도입 텍스트나 단계 2 캐릭터 소개 멘트로 시나리오 저자가 직접 풀어 쓴다)

### User Story E2-02

- **As a** 플레이어
- **I want to** 새 라운드가 시작되면 카드 안의 "이번 라운드 목표"가 자동으로 갱신되고

- **Given:** 시나리오 메타에 캐릭터 × 라운드 Objective 매트릭스가 정의되어 있다

- **Then:** 카드 "현재 라운드 목표" 영역이 라운드 N 칸으로 자동 교체된다 (이전 라운드 회상 컨트롤은 MVP 밖)

### User Story E2-03

- **Summary:** 단계 9-B에서 미션이 처음 노출되고 그 자리에서 ✓/✗로 체크한다

#### Use Case

- **As a** 플레이어

- **so that** 미션을 미리 알아서 게임 흐름을 왜곡하는 일 없이, 끝난 뒤에 회상으로 자가 체크할 수 있다

- **When:** 플레이어가 카드를 연다
- **Then:** 미션 영역은 노출되지 않거나 "단계 9-B에서 공개" 자리표시자가 보인다
- **and:** 단계 9-B 진입 시 카드 미션 영역에 1–3개 미션이 처음으로 노출되고 각 항목에 ✓/✗ 토글이 표시된다

### User Story E2-04

- **Summary:** 카드 안에서 "내가 가진 단서"와 "접근권만 가진 단서"가 분리되어 보인다

#### Use Case

- **so that** 누구에게 무엇을 건넬 수 있는지·어느 장소에서 나온 단서인지를 한눈에 판단할 수 있다

#### Acceptance Criteria

- **When:** 플레이어가 카드 아이템 영역을 연다
- **Then:** "소유 아이템"과 "접근권 보유 아이템" 두 섹션이 시각적으로 분리되고, `origin_location_id`가 매핑된 단서에는 [발견 장소 아이콘 + 이름]이 표시되며 (미매핑 단서는 장소 라벨 없이 노출), 라벨이 표시되는 단서는 E2-05의 동일한 [아이콘 + 이름] 양식을 그대로 따른다

### User Story E2-05

- **Summary:** L-Vis 1 — 장소 라벨이 모든 화면에서 일관된다

#### Use Case

- **As a** 플레이어
- **I want to** 라운드 진입 카드·알리바이 라벨·단서 발견 장소 라벨이 모두 같은 [아이콘 + 이름 + 1줄 분위기] 조합으로 일관되고
- **so that** "그 옥상 정원이 그 옥상 정원이 맞나?"를 의심하지 않고 알리바이 교차 검증을 머릿속에서 곧장 수행할 수 있다

- **Given:** 단계 10이 종료되었다
- **When:** 종료 화면이 렌더링된다
- **Then:** 설문은 모달이 아닌 인라인 카드로 종료 화면에 동거하고, 1번 문항 영역에 플랫폼 점수 슬라이더와 작품 점수 슬라이더(둘 다 플랫폼 고정 문구) 2개가 한 화면에 노출되며 (각각 독립 응답·미응답 허용), 2번 영역에 자유 텍스트 한 칸(80자)이 노출되고, "응답하기"·"건너뛰기" 두 컨트롤이 동일한 시각 가중(크기·색·위치 우선순위)으로 노출되며, 둘 중 무엇을 눌러도 다음 화면(세션 종료) 진입이 막히지 않는다

---

### User Story E2-12

- **Summary:** 세션 종료 화면이 "수고했어요" 메시지와 본인 미션 한 줄 요약을 표시한다

#### Use Case

- **As a** 플레이어
- **I want to** 설문 카드(또는 건너뛰기) 다음에 종료 화면을 보고
- **so that** "이 판이 끝났구나"라는 마침이 자연스럽게 오고, 내가 직전에 ✓/✗로 표시한 미션 결과가 한 줄로 정리되어 친구들과 즉석에서 짧게 회상할 수 있다

#### Acceptance Criteria

- **Scenario:** 종료 화면 — "수고했어요" + 본인 미션 한 줄 요약 + 외부 공유 없음
- **Given:** 본인이 참여한 세션이 종료되어 설문 카드 다음 화면이 렌더링된다
- **When:** 플레이어가 종료 화면을 본다
- **Then:** "수고했어요" 메시지와 본인 미션·자가 체크 결과(✓/✗) 한 줄 요약이 표시되며, 별도 회상 화면(아이템 행위 이력 등)·외부 공유·다운로드 컨트롤은 노출되지 않는다 (Keepsake 회상 화면은 MVP 밖)
