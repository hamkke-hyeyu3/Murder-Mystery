## Epic 1 — 시나리오 진행 엔진 (런타임 상태 기계)

PRD §7.2 Epic 1 책임 매핑. 상태 변화·ACL·브로드캐스트·메타 파싱이 본 Epic에 귀속.

### User Story E1-01

- **Summary:** 호스트가 회원가입 없이 시나리오를 골라 초대 번호를 띄운다

#### Use Case

- **As a** 호스트
- **I want to** 앱을 열자마자 시나리오를 고르고 초대 번호를 띄우고
- **so that** 친구들이 모인 그 자리에서 회원가입 마찰 없이 5분 안에 단계 1로 들어갈 수 있다

#### Acceptance Criteria

- **Scenario:** 호스트가 첫 진입에서 시나리오 카탈로그를 거쳐 초대 번호를 생성
- **Given:** 호스트가 앱을 처음 연다
- **and Given:** 회원가입·로그인 단계가 노출되지 않는다
- **and Given:** 카탈로그에 최소 1편의 시나리오가 노출된다
- **When:** 시나리오를 선택하고 "세션 시작"을 탭한다
- **Then:** 6자리 숫자 초대 번호가 호스트 화면에 표시되고 게스트 합류 대기 상태로 전환된다

---

### User Story E1-02

- **Summary:** 게스트가 닉네임만으로 세션에 합류한다

#### Use Case

- **As a** 게스트
- **I want to** 호스트가 불러주는 6자리 번호와 닉네임만 입력해 세션에 합류하고
- **so that** 회원가입·로그인을 거치지 않고 바로 캐릭터 배정 화면을 받을 수 있다

#### Acceptance Criteria

- **Scenario:** 게스트가 초대 번호로 합류
- **Given:** 호스트가 합류 대기 상태에 있다
- **and Given:** 게스트가 유효한 6자리 초대 번호를 알고 있다
- **and Given:** 게스트는 어떤 가입·인증 화면도 거치지 않는다
- **When:** 초대 번호와 닉네임을 입력하고 "합류"를 탭한다
- **Then:** 게스트 단말은 합류 확정 피드백과 함께 합류 대기 화면으로 전환되고, 호스트 화면 합류자 목록에도 해당 닉네임이 즉시 추가된다

### User Story E1-03

- **Summary:** 호스트가 인원을 확정하면 모두가 단계 1(도입)로 동시 전환된다

#### Use Case

- **As a** 호스트
- **I want to** 합류 인원이 확정된 시점에 "시작"을 탭해 모두를 단계 1로 보내고
- **so that** 진행자 1인이 화면을 일일이 안내하지 않아도 전원이 같은 페이즈에 정렬된다

#### Acceptance Criteria

- **Scenario:** 호스트의 시작 탭이 모든 합류자 단말을 단계 1로 동기 전환
- **Given:** 합류자 수가 시나리오 캐릭터 수와 정확히 일치한다
- **and Given:** 모든 합류자 단말이 합류 대기 화면을 보고 있다
- **When:** 호스트가 "시작"을 탭한다
- **Then:** 모든 단말이 단계 1(도입) 텍스트/오디오 자동 재생 화면으로 전환되며, 인원 불일치 상태에서는 "시작" 컨트롤이 비활성화되어 탭 자체가 발생하지 않는다

### User Story E1-04

- **Summary:** 캐릭터가 자동 배정되고 개인 정보가 본인에게만 도착한다

#### Use Case

- **As a** 플레이어
- **I want to** 단계 2에서 내 캐릭터와 비밀·동기 같은 개인 정보를 내 화면에서만 받고
- **so that** 옆 사람의 화면을 훔쳐보지 않으면 내 비밀이 보호된다는 걸 신뢰하고 몰입할 수 있다

#### Acceptance Criteria

- **Scenario:** 단계 2에서 캐릭터 자동 배정 + 개인 정보 1대1 전달 + `public` 필드만 전원 동기 노출
- **Given:** 단계 1이 끝났다
- **and Given:** 합류 인원 = 시나리오 캐릭터 수
- **and Given:** 각 캐릭터 카드의 필드는 `disclosure` 라벨 (`public`/`shareable`/`secret`)을 갖는다 (시나리오 저자 미선언 시 플랫폼 디폴트: 이름·직업 = `public`, 비밀·동기·알리바이·관계 = `shareable`)
- **When:** 엔진이 단계 2로 전환한다
- **Then:** 각 플레이어 단말의 본인 카드에는 모든 필드(`public` + `shareable` + `secret`)가 노출되고, 모든 캐릭터의 `public` 필드는 전원 단말에 동기되어 "공개 캐릭터 정보" 화면(E2-01b)에서 열람 가능한 상태가 되며, `shareable`·`secret` 필드는 본인 카드 외 어떤 화면에도 노출되지 않는다

### User Story E1-04b

- **Summary:** 단계 3 규칙 공지가 인앱 튜토리얼 + 맥락 힌트로 대체된다

#### Use Case

- **As a** 플레이어
- **I want to** 단계 3에서 규칙을 호스트 1인의 낭독으로 듣는 대신 내 단말의 인앱 튜토리얼로 받고 이후 필요한 순간에 JIT 맥락 힌트로 다시 떠오르고
- **so that** "지금 뭘 해도 되는지"를 다른 사람에게 묻지 않고 진행할 수 있고, 규칙 미숙지로 인한 초반 이탈을 줄인다

#### Acceptance Criteria

- **Scenario:** 단계 3 인앱 튜토리얼 + `lying_policy` 안내 + 이후 페이즈에서 JIT 맥락 힌트
- **Given:** 단계 2가 종료되었다
- **and Given:** 시나리오 메타가 `lying_policy` (4개 enum 중 하나, 기본 `all_players`)를 선언한다
- **When:** 엔진이 단계 3에 진입한다
- **Then:** 각 플레이어 단말에 인앱 튜토리얼이 표시되어 본 시나리오의 `lying_policy` 값이 *"이 시나리오에서는 [정책 설명] 규칙이 적용됩니다"* 형태로 1회 안내되고, 각자 "확인" 탭으로 본인의 통과 상태를 표시하며, 모든 합류자가 통과를 표시한 시점에 엔진이 L1으로 자동 전환되고, 이후 L1·L2 페이즈는 *세션 전체에서 처음 진입할 때* 1회 JIT 힌트가 자동 노출되며 (라운드마다 반복 노출되지 않음) 단계 8 첫 진입 시에도 1회 노출된다

### User Story E1-05

- **Summary:** 라운드 시작 시 라운드별 프롬프트와 타이머가 자동으로 켜진다

#### Use Case

- **As a** 플레이어
- **I want to** 새 라운드가 시작될 때 "이번 라운드는 무엇을 하는 시간인지"를 화면에서 받고
- **so that** 진행자에게 "지금 뭐 하는 거야?"를 묻지 않아도 즉시 대화에 들어갈 수 있다

#### Acceptance Criteria

- **Scenario:** 루프 라운드 진입 시 프롬프트 + 타이머 자동 노출
- **Given:** 시나리오 메타가 총 라운드 수 N(MVP는 고정 횟수)과 각 라운드별 프롬프트·제한 시간을 선언한다
- **and Given:** 직전 라운드가 종료되었거나 단계 3이 종료되어 루프 첫 진입 시점이다
- **When:** 엔진이 라운드 k(1 ≤ k ≤ N)로 진입한다
- **Then:** 모든 단말에 라운드 k 프롬프트 + 카운트다운 타이머가 동시에 표시되고 시간 경고 임계점에서 시각/햅틱 알림이 울린다

### User Story E1-06

- **Summary:** 시나리오가 허용한 경우에만 밀담을 n명에게 신청·진행·종료할 수 있다

#### Use Case

- **As a** 플레이어
- **I want to** 시나리오가 밀담을 허용할 때 1명 이상의 다른 플레이어에게 밀담을 신청하고 수락한 사람들과만 "밀담 중" 상태로 들어가고
- **so that** 누가 누구와 이야기 중인지를 (저자가 의도한 가시성 범위 안에서) 외부가 인지하면서도 전략적 동맹·정보 교환의 사적 채널을 가질 수 있다

#### Acceptance Criteria

- **Scenario:** 밀담 상태 기계 — 허용 시나리오에서 n명 신청 + 수락자만 참여 + 0 수락자 자동 소멸 + 라운드 한도 분기 + 가용 대상자 0명 시 비활성
- **Given:** 시나리오 메타에 `allow_private_talk: true`가 선언되어 있다
- **and Given:** 현재 페이즈가 L1(알리바이·심문·변론)이다
- **and Given:** 시나리오 메타가 `max_private_talks_per_round`를 선언한 경우, 본 라운드 본 신청자의 누적 신청 횟수가 한도 미만이다
- **When:** A가 1명 이상의 대상자에게 밀담을 신청하고 각 대상자가 수락 또는 거절을 선택한다
- **Then:** 신청 가능한 대상자(다른 밀담에 참여 중이 아닌 사람)가 0명이면 신청 컨트롤이 비활성화되어 신청 자체가 발생하지 않고, 가용 대상자가 1명 이상인 경우 신청이 발송되어 수락자가 1명 이상이면 A + 수락자만으로 밀담이 성립해 참여자 단말이 "밀담 중" 상태로 전환되며, 수락자가 0명이면 밀담은 불성립으로 자동 소멸하고, 성립한 밀담은 참여자 자발 종료·라운드 경계 도달 시 자동 종료되며, 라운드 한도 도달 시 신청 컨트롤은 다음 라운드 진입 전까지 비활성화된다

### User Story E1-07

- **Summary:** 두 플레이어가 아이템을 1:1 교환하면 양측이 두 아이템에 모두 접근권을 얻는다

#### Use Case

- **As a** 플레이어
- **I want to** 내 단서 카드를 다른 플레이어의 단서 카드와 맞바꾸고
- **so that** 소유는 옮기되 "어차피 봤던 단서"는 내 기억 부담 없이 계속 열람할 수 있다

#### Acceptance Criteria

- **Scenario:** 아이템 교환(exchange) — 1:1 단일 쌍
- **Given:** A는 아이템 X를, B는 아이템 Y를 소유한다
- **When:** A·B가 X↔Y 교환을 합의 확정한다
- **Then:** 소유권은 X→B, Y→A로 이동하고 A·B 모두 X·Y 두 아이템에 대한 접근권을 영구 보유하며 (양측이 사전에 일부 또는 전부의 접근권을 이미 갖고 있었는지 여부와 무관), 메타 층 배너에 "라운드 N: A ↔ B (교환)"이 양방향 화살표로 라운드 꼬리표와 함께 게시된다 (시나리오 저자가 `item_exchange_log_visibility: false`로 끈 경우 본 배너는 비표시)

### User Story E1-08

- **Summary:** 단서 소유자가 단서를 전원에게 공개한다

#### Use Case

- **As a** 플레이어
- **I want to** 내가 가진 단서를 전체에게 공개하고
- **so that** 모두가 같은 정보를 본 상태에서 추리 토론을 할 수 있다

#### Acceptance Criteria

- **Scenario:** 아이템 전체 공유(share_all)
- **Given:** A가 아이템 X를 소유한다
- **When:** A가 X에 대해 "전체 공유"를 확정한다
- **Then:** X의 소유권은 A에 그대로 유지되고 모든 플레이어에게 X 접근권이 부여되며, 메타 층 배너에 "라운드 N: A → 전원 (전체 공유)"가 게시된다 (시나리오 저자가 `item_share_all_log_visibility: false`로 끈 경우 본 배너는 비표시)

### User Story E1-09

- **Summary:** 단서 소유자가 지정한 N명에게만 단서를 공개한다

#### Use Case

- **As a** 플레이어
- **I want to** 내 단서를 내가 고른 일부 플레이어에게만 공개하고
- **so that** 동맹·역할극 흐름을 깨지 않으면서 정보를 전략적으로 분배할 수 있다

#### Acceptance Criteria

- **Scenario:** 아이템 부분 공유(share_partial) — N명 지정
- **Given:** A가 아이템 X를 소유한다
- **and Given:** A가 1명 이상의 다른 플레이어를 공유 대상으로 지정한다
- **When:** A가 X 부분 공유를 확정한다
- **Then:** X의 소유권은 A 유지, 지정된 수신자들에게만 접근권이 부여되고 비대상자 화면에는 X의 내용이 보이지 않으며, 메타 층 배너에 "라운드 N: A → 영희, 철수, … (부분 공유)" 형태로 모든 수신자 닉네임이 명시되어 게시된다 (시나리오 저자가 `item_share_partial_log_visibility: false`로 끈 경우 본 배너는 비표시)

### User Story E1-10

- **Summary:** 라운드 진입 시 각자에게 조사할 가상 장소가 배정되고 그 장소의 단서가 도착한다

#### Use Case

- **As a** 플레이어
- **I want to** 새 라운드가 시작될 때 "이번 라운드 당신이 조사할 장소"를 카드로 받고 그 장소의 단서가 내 단말에 도착하고
- **so that** 알리바이 발화에 가상 공간 앵커가 생기고, 전원이 동시에 같은 장소를 본다는 마찰 없이 각자 다른 장소를 조사할 수 있다

#### Acceptance Criteria

- **Scenario:** L2 라운드 진입 — 조사 장소 카드 + 단서 ACL 부여
- **Given:** 시나리오 메타가 캐릭터 × 라운드 매트릭스로 `assigned_location_id`를 선언한다
- **and Given:** 해당 장소에 `origin_location_id`가 매핑된 아이템이 존재한다
- **When:** 엔진이 라운드 N의 L2 단계에 진입한다
- **Then:** 각 플레이어 단말에 "이번 라운드 조사 장소: [아이콘 + 이름 + 1줄 분위기]" 카드가 표시되고, 그 장소의 단서가 해당 플레이어에게 도착한다 (= 기존 Item ACL 메커니즘 그대로 재사용, 새 ACL 규칙 도입 없음)

### User Story E1-11

- **Summary:** 라운드 누적 단서가 사라지지 않는다

#### Use Case

- **As a** 플레이어

## Epic 2 — 캐릭터 카드 UI + 시각화

PRD §7.2 Epic 2 책임 매핑. Epic 1이 발생시킨 상태·메타·이벤트의 모든 표면이 본 Epic에 귀속.

---

### User Story E2-01

- **Summary:** 캐릭터 카드 한 번의 탭으로 핵심 정보에 도달한다

#### Use Case

- **As a** 플레이어
- **I want to** 어떤 화면에서든 한 번의 탭으로 내 캐릭터 카드를 열어 이름·배경·동기·알리바이·비밀·관계·말투 가이드를 보고
- **so that** "내 캐릭터가 뭐였더라"를 떠올리는 데 멘탈을 쓰지 않고 곧장 대화에 복귀할 수 있다

#### Acceptance Criteria

- **Scenario:** 카드 단일 탭 도달 — 말투·라운드 목표·미션·아이템·알리바이 장소 동거 + 필드별 disclosure 뱃지
- **Given:** 플레이어가 게임 진행 중인 어떤 페이즈에 있다
- **and Given:** 시나리오 저자가 본 캐릭터에 말투 가이드를 작성했다 (선택 필드 — 미작성 시 카드 상단 영역은 비표시)
- **and Given:** 본 캐릭터의 각 카드 필드는 `disclosure` 라벨(`public`/`shareable`/`secret`)을 갖는다
- **When:** 플레이어가 카드 진입 컨트롤을 1회 탭한다
- **Then:** 단일 카드 표면에서 이름·배경·동기·알리바이·비밀·관계 본문 + 말투 가이드(상단 상시) + 현재 라운드 목표 영역(E2-02) + 미션 영역(E2-03, 단계 9-B 이전엔 자리표시자) + 아이템 섹션(E2-04, 소유/접근권 분리) + 내 알리바이 장소 라벨(E2-05) 모두에 추가 탭 없이 도달 가능하고, 본문 정보 필드(이름·직업·배경·동기·알리바이·비밀·관계 + 시나리오 저자 커스텀 필드) 옆에는 `disclosure` 라벨이 시각 뱃지로 표시되어 (`public`은 🔓, `shareable`은 무뱃지, `secret`은 🔒) 본인이 어떤 정보가 공개·공유 가능·비밀인지 자기 검열할 수 있으며, 미션 영역은 단계 9-B 가드(E2-03)를 따르므로 `disclosure` 뱃지 적용 대상이 아니다

### User Story E2-01b

- **Summary:** 다른 캐릭터의 공개 정보를 한 화면에서 조망한다

#### Use Case

- **As a** 플레이어
- **I want to** 단계 2(캐릭터 소개) 이후 어떤 페이즈에서든 "공개 캐릭터 정보" 화면을 열어 모든 캐릭터의 `public` 필드(기본값으로 이름·직업)를 한 화면에서 보고
- **so that** 알리바이 교차 검증·관계 추리에 필요한 공통 정보를 다른 사람에게 묻지 않고 즉시 참조할 수 있다

#### Acceptance Criteria

- **Scenario:** 공개 캐릭터 정보 섹션 — 모든 캐릭터의 `public` 필드 동기 노출
- **Given:** 단계 2가 종료되어 캐릭터 배정과 `public` 정보 동기 노출(E1-04)이 완료되었다
- **and Given:** 시나리오 메타가 각 캐릭터의 `public`/`shareable`/`secret` 필드 라벨을 갖는다 (저자 미선언 시 플랫폼 디폴트)
- **When:** 플레이어가 "공개 캐릭터 정보" 진입 컨트롤을 탭한다
- **Then:** 모든 캐릭터가 카드 그리드/리스트로 노출되고 각 카드에 해당 캐릭터의 `public` 필드만 표시되며 (디폴트로 이름·직업), `shareable`·`secret` 필드는 본 화면 어디에도 노출되지 않고, 본 화면은 단계 2 종료 이후 어떤 페이즈에서도 호출 가능하다

### User Story E2-02

- **Summary:** 라운드가 바뀌면 카드의 라운드 목표가 자동으로 갈아 끼워진다

#### Use Case

- **so that** 시나리오 저자가 의도한 라운드별 행동선을 놓치지 않으면서도 흐름을 거슬러 올라갈 수 있다

#### Acceptance Criteria

- **Given:** 시나리오 메타에 캐릭터 × 라운드 Objective 매트릭스가 정의되어 있다
- **When:** 엔진이 라운드 N으로 전환한다
- **Then:** 카드 "현재 라운드 목표" 영역이 라운드 N 칸으로 자동 교체되고, 별도 컨트롤로 라운드 1~N-1의 목표를 읽기 전용으로 열람할 수 있다

### User Story E2-03

- **Summary:** 단계 9-B에서 미션이 처음 노출되고 그 자리에서 ✓/✗로 체크한다

#### Use Case

- **I want to** 단계 9-B에서 처음으로 내 미션이 카드에 펼쳐지고 즉시 ✓/✗를 누르고
- **so that** 미션을 미리 알아서 게임 흐름을 왜곡하는 일 없이, 끝난 뒤에 회상으로 자가 체크할 수 있다

- **Scenario:** 단계 9-B 진입 전 미션 비공개 + 진입 시 카드 노출

- **When:** 플레이어가 카드를 연다
- **Then:** 미션 영역은 노출되지 않거나 "단계 9-B에서 공개" 자리표시자가 보인다
- **and:** 단계 9-B 진입 시 카드 미션 영역에 1–3개 미션이 처음으로 노출되고 각 항목에 ✓/✗ 토글이 표시된다

### User Story E2-04

- **Summary:** 카드 안에서 "내가 가진 단서"와 "접근권만 가진 단서"가 분리되어 보인다

#### Use Case

- **As a** 플레이어
- **I want to** 내 카드의 아이템 영역에서 "내 소유"와 "접근권 보유"가 따로 묶여 보이고 각 단서에 발견 장소 라벨이 붙어 있고
- **so that** 누구에게 무엇을 건넬 수 있는지·어느 장소에서 나온 단서인지를 한눈에 판단할 수 있다

#### Acceptance Criteria

- **Scenario:** 두 섹션 분리 + 장소 라벨 일관 노출
- **Given:** 플레이어가 1개 이상의 단서를 소유하거나 접근권으로 보유한다
- **When:** 플레이어가 카드 아이템 영역을 연다
- **Then:** "소유 아이템"과 "접근권 보유 아이템" 두 섹션이 시각적으로 분리되고, `origin_location_id`가 매핑된 단서에는 [발견 장소 아이콘 + 이름]이 표시되며 (미매핑 단서는 장소 라벨 없이 노출), 라벨이 표시되는 단서는 E2-05의 동일한 [아이콘 + 이름] 양식을 그대로 따른다

### User Story E2-05

- **Summary:** L-Vis 1 — 장소 라벨이 모든 화면에서 일관된다

#### Use Case

- **I want to** 라운드 진입 카드·알리바이 라벨·단서 발견 장소 라벨이 모두 같은 [아이콘 + 이름 + 1줄 분위기] 조합으로 일관되고
- **so that** "그 옥상 정원이 그 옥상 정원이 맞나?"를 의심하지 않고 알리바이 교차 검증을 머릿속에서 곧장 수행할 수 있다

- **Scenario:** L-Vis 1 일관 노출 + 아이콘 fallback
- **Given:** 시나리오 메타에 `Location.name`·`description`이 정의되어 있다
- **and Given:** `Location.icon`은 시나리오 저자가 선택한 이모지/아이콘 키 또는 미선언 상태다
- **When:** 플레이어가 라운드 진입 카드, 캐릭터 카드의 알리바이 라벨, 단서 카드의 발견 장소 라벨을 각각 본다
- **Then:** 세 위치 모두 동일한 아이콘 + 이름이 같은 시각 양식으로 노출되며, `icon` 미선언 시에는 세 위치 모두 동일한 기본 아이콘 `📍`가 일관되게 적용된다

### User Story E2-06

- **When:** 플레이어가 장소 오버뷰 진입 컨트롤을 탭한다
- **Then:** 모든 장소가 그리드/리스트로 노출되고 각 카드에 (이름·아이콘·1줄 분위기·알리바이 캐릭터 수·도착 단서 수)가 표시된다

### User Story E2-07

- **Summary:** L-Vis 3 — 인접 그래프에서 동선을 사람 눈으로 추리한다

#### Use Case

- **As a** 플레이어
- **I want to** 장소를 노드로, 인접을 엣지로 표현한 그래프에서 다른 캐릭터의 알리바이 위치 배지를 보고
- **so that** "옥상에서 도서관까지 가려면 복도를 거쳐야 한다" 같은 동선 추리를 *내가* 하면서 추리의 재미를 앱에 빼앗기지 않는다

#### Acceptance Criteria

- **Given:** 시나리오 메타에 `adjacent_to`로 인접 쌍이 선언되어 있다

- **When:** 플레이어가 인접 그래프 화면에 진입해 임의의 노드를 탭한다
- **Then:** 노드/엣지가 자동 렌더링되어 각 노드에 알리바이 캐릭터 배지가 표시되고, 노드 탭 시 해당 장소의 L-Vis 1 카드(아이콘 + 이름 + 분위기 텍스트)가 팝업으로 열리며, 어떤 동선 모순도 자동으로 표시·강조되지 않는다

### User Story E2-08

- **Summary:** 아이템 이벤트 타임라인에서 누가·누구에게·몇 라운드·어떤 행위였는지 역순으로 본다

#### Use Case

- **As a** 플레이어
- **I want to** 세션 내내 발생한 아이템 행위(교환·전체 공유·부분 공유)를 라운드 꼬리표와 함께 역순 리스트로 열람하고
- **so that** "그 단서는 누구 손에서 누구 손으로 갔더라"를 다른 사람에게 묻지 않고 추리 흐름을 유지할 수 있다

#### Acceptance Criteria

- **Scenario:** 메타 층 타임라인 — 아이템 3행위 한정 + 라운드 꼬리표 + 행위 유형별 플래그 필터
- **Given:** 1회 이상의 아이템 행위(교환·전체 공유·부분 공유)가 발생했다
- **and Given:** 시나리오 메타가 아이템 행위 3개 플래그(`item_exchange_log_visibility`·`item_share_all_log_visibility`·`item_share_partial_log_visibility`) 각각의 값을 갖는다
- **When:** 플레이어가 아이템 이벤트 타임라인을 연다
- **Then:** 플래그가 `true`인 행위 유형만 [라운드 N · 행위자 → 대상 · 행위 종류] 포맷으로 역순 리스트에 노출되어 일부 유형이 `false`인 시나리오에서는 해당 유형이 누락된 채 다른 유형은 정상 노출되며, 본 타임라인에는 밀담 이벤트가 포함되지 않고 (밀담 가시성은 E2-09 배너에서 처리), 어떤 경우에도 아이템 *내용*은 본 타임라인에 표시되지 않는다

### User Story E2-09

- **Summary:** "누가 누구와 밀담 중"이 전체 화면 상단 배너에 보인다

#### Use Case

- **As a** 플레이어
- **I want to** 밀담이 진행 중일 때 그 사실 자체가 전체 단말 상단 배너에 떠 있는 것을 보고
- **so that** "지금 둘이 따로 얘기하고 있구나"가 자연스럽게 게임 정보가 되어 추리 압박이 발생한다

#### Acceptance Criteria

- **Scenario:** 밀담 상태 배너 — `private_talk_log_visibility` 플래그에 따른 노출 분기
- **Given:** 시나리오에서 밀담이 허용되어 있고 1건 이상 진행 중이다
- **and Given:** 시나리오 메타의 `private_talk_log_visibility` 값이 정해져 있다 (기본 `true`)
- **When:** 플레이어가 어떤 화면이든 본다
- **Then:** 플래그가 `true`이면 모든 단말 상단에 "A ↔ B(외 N명) 밀담 중" 배너가 표시되고, 플래그가 `false`이면 배너는 참여자 단말에서만 노출되며 비참여자 단말에는 어떤 진행 표지도 노출되지 않고, 어느 경우든 밀담 종료 시점에 해당 배너는 즉시 사라진다 (ACL·텔레메트리 수집은 플래그와 무관)

### User Story E2-10

### User Story E2-11

- **Summary:** 포스트 엔딩 설문이 인라인 카드로 동거하고 플랫폼·작품 점수를 분리해서 받는다

#### Use Case

- **As a** 플레이어
- **I want to** 종료 화면에서 모달 팝업이 아닌 인라인 카드로 설문을 받고 한 화면에서 플랫폼 점수와 작품 점수를 별도 슬라이더로 응답하고 자유 텍스트는 한 칸에 적고 "응답"·"건너뛰기" 두 버튼이 시각적으로 동등해 보이고
- **so that** "플랫폼은 좋은데 시나리오는 별로" 같은 이중 평가를 분리해서 남길 수 있고, 거절이 어렵게 느껴지는 압박 없이 자연스럽게 응답하거나 빠져나갈 수 있다

#### Acceptance Criteria

- **Scenario:** 인라인 카드 + 두 차원 점수 동거 + 자유 텍스트 한 칸 + 동일 시각 가중 + 미응답 비차단
- **Given:** 단계 10이 종료되었다
- **When:** 종료 화면이 렌더링된다
- **Then:** 설문은 모달이 아닌 인라인 카드로 종료 화면에 동거하고, 1번 문항 영역에 플랫폼 점수 슬라이더(고정 문구)와 작품 점수 슬라이더(저자 오버라이드 가능 문구) 2개가 한 화면에 노출되며 (각각 독립 응답·미응답 허용), 2번 영역에 자유 텍스트 한 칸(80자)이 노출되고, "응답하기"·"건너뛰기" 두 컨트롤이 동일한 시각 가중(크기·색·위치 우선순위)으로 노출되며, 둘 중 무엇을 눌러도 다음 화면(세션 종료·Keepsake) 진입이 막히지 않는다
