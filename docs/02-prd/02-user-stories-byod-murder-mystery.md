## Epic 1 — 시나리오 진행 엔진 (런타임 상태 기계)

PRD §7.2 Epic 1 책임 매핑. 상태 변화·ACL·브로드캐스트·메타 파싱이 본 Epic에 귀속.

### User Story E1-01

- **Summary:** 호스트가 회원가입 없이 시나리오를 골라 초대 번호를 띄운다

#### Use Case

- **As a** 호스트
- **I want to** 앱을 열자마자 시나리오를 고르고 초대 번호를 띄우고
- **so that** 친구들이 모인 그 자리에서 회원가입 마찰 없이 5분 안에 단계 1로 들어갈 수 있다

#### Acceptance Criteria

- **Scenario:** 호스트가 첫 진입에서 시나리오 카탈로그를 거쳐 초대 번호를 생성
- **Given:** 호스트가 앱을 처음 연다
- **and Given:** 회원가입·로그인 단계가 노출되지 않는다
- **and Given:** 카탈로그에 최소 1편의 시나리오가 노출된다
- **When:** 시나리오를 선택하고 *"세션 만들기"*를 탭한다
- **Then:** 6자리 숫자 초대 번호가 호스트 화면에 표시되고 게스트 합류 대기 상태로 전환된다 (본 버튼 라벨은 단계 1 전환 트리거인 *"게임 시작"*(E1-03)과 명시적으로 분리되어, 두 단계의 호스트 액션이 동일 라벨로 혼동되지 않도록 한다)

### User Story E1-02

- **Summary:** 게스트가 닉네임만으로 세션에 합류한다

#### Use Case

- **As a** 게스트
- **I want to** 호스트가 불러주는 6자리 번호와 닉네임만 입력해 세션에 합류하고
- **so that** 회원가입·로그인을 거치지 않고 바로 캐릭터 배정 화면을 받을 수 있다

#### Acceptance Criteria

- **Scenario:** 게스트가 초대 번호로 합류
- **Given:** 호스트가 합류 대기 상태에 있다
- **and Given:** 게스트가 유효한 6자리 초대 번호를 알고 있다
- **and Given:** 게스트는 어떤 가입·인증 화면도 거치지 않는다
- **When:** 초대 번호와 닉네임을 입력하고 "합류"를 탭한다
- **Then:** 게스트 단말은 합류 확정 피드백과 함께 합류 대기 화면으로 전환되고, 호스트 화면 합류자 목록에도 해당 닉네임이 즉시 추가된다

### User Story E1-02b

- **Summary:** 네트워크 끊김·앱 크래시 후 같은 초대 번호 + 닉네임으로 재합류해 자기 자리로 복귀한다

#### Use Case

- **As a** 플레이어 (호스트·게스트 무관)
- **I want to** 폰이 잠시 끊기거나 앱이 죽었을 때 같은 초대 번호와 닉네임을 다시 입력해 내가 있던 그 자리(같은 캐릭터·같은 단서·같은 라운드)로 즉시 복귀하고
- **so that** 친구들 분위기를 깨지 않고 다시 합류해 게임을 계속할 수 있다

#### Acceptance Criteria

- **Scenario:** 동일 초대 번호 + 동일 닉네임 재진입 시 기존 슬롯 재바인딩 (진행 중 세션 한정)
- **Given:** 세션 상태가 `in_progress` (단계 1 이후)이며, 닉네임 *N*으로 합류했던 단말이 일시적으로 오프라인 또는 앱 종료 상태가 되었다
- **and Given:** 세션은 다른 단말에 의해 계속 진행 중이다 (`paused` 상태는 MVP에 존재하지 않음 — PRD §5.2 세션 상태 머신 참조)
- **When:** 같은 단말 또는 동일 닉네임 *N*을 가진 다른 단말이 같은 초대 번호 + 닉네임 *N*을 입력해 합류를 시도한다
- **Then:** 새 합류로 처리되지 않고 **기존 슬롯에 재바인딩**되어 본인 캐릭터·소유 아이템·접근권 보유 아이템·현재 라운드·**단계 3 튜토리얼 통과 상태**·9-B 체크 상태(잠금 포함)가 그대로 복원되고 (단계 3 튜토리얼은 이미 통과 상태이므로 재노출되지 않으며 곧장 현재 페이즈로 진입), 합류자 목록에 닉네임이 중복 추가되지 않으며, 다른 플레이어 단말에는 *"[N] 재합류"* 같은 시스템 알림이 발생하지 않는다 (몰입 보존 — 끊김 사실 자체를 게임 정보로 만들지 않음). **호스트가 재합류한 경우 호스트 권한(9-B 강제 진행)도 자동 복원**된다 (호스트 식별은 세션 생성 시 닉네임 기준)
- **and Then (NB1 — 진행 중 세션의 새 닉네임 합류 차단):** `session_state == in_progress`인 세션에 *기존 슬롯에 없는* 새 닉네임으로 합류 시도가 들어오면 *"이미 시작된 세션입니다 — 합류할 수 없어요"* 메시지로 거부되며 합류자 목록·J에는 변화가 없다 (진행 중 세션은 인원 추가 자체가 차단되므로 E1-03b의 *"X명 초과"* 인라인 표시는 발동하지 않음 — E1-03b는 합류 대기(`session_state == lobby`) 화면 한정)
- **and Then (NB2 — 합류 대기 단계의 닉네임 중복은 재합류로 오인하지 않음):** `session_state == lobby`(아직 *"게임 시작"* 미탭)에서 동일 닉네임 입력 시도는 **재합류가 아니라 닉네임 중복 충돌**로 처리된다 — 즉시 *"이미 사용 중인 닉네임입니다"* 거부 메시지로 재입력 요구 (Q17 보류 정책의 임시 디폴트, 자동 suffix 등 정식 정책은 Q17 결정 시 교체). 본 분기와 위 *"진행 중 세션 재합류"* 분기는 `session_state` 값으로 명확히 분리됨
- **MVP 한계:** 끊김 동안 발생한 단서·밀담·아이템 상태 변경은 모두 monotonic이므로 재합류 시 자동 따라잡기 가능. 그러나 *끊긴 동안의 발화·대면 토론*은 재합류자가 친구들에게 구두로 따라잡아야 함 (앱 차원의 "놓친 이벤트 요약" 화면은 후속)

### User Story E1-03

- **Summary:** 호스트가 인원을 확정하면 모두가 단계 1(도입)로 동시 전환된다

#### Use Case

- **As a** 호스트
- **I want to** 합류 인원이 확정된 시점에 "시작"을 탭해 모두를 단계 1로 보내고
- **so that** 진행자 1인이 화면을 일일이 안내하지 않아도 전원이 같은 페이즈에 정렬된다

#### Acceptance Criteria

- **Scenario:** 호스트의 시작 탭이 모든 합류자 단말을 단계 1로 동기 전환
- **Given:** 합류자 수가 시나리오 캐릭터 수와 정확히 일치한다
- **and Given:** 모든 합류자 단말이 합류 대기 화면을 보고 있다
- **When:** 호스트가 *"게임 시작"*을 탭한다
- **Then:** 모든 단말이 단계 1(도입) 텍스트/오디오 자동 재생 화면으로 전환되며, 인원 불일치 상태에서는 *"게임 시작"* 컨트롤이 비활성화되어 탭 자체가 발생하지 않는다 (본 라벨은 시나리오 선택 단계의 *"세션 만들기"*(E1-01)와 명시적으로 분리)

### User Story E1-03b

- **Summary:** 인원 불일치 상태에서는 부족·초과 인원이 호스트 화면에 사유로 표시된다

#### Use Case

- **As a** 호스트
- **I want to** 합류자 수가 시나리오 캐릭터 수와 맞지 않을 때 "시작" 비활성 사유가 화면에 한 줄로 보이고
- **so that** 친구들에게 *"왜 시작이 안 되지?"*를 디버깅하느라 분위기가 식지 않고 즉시 다음 행동(부르기/내보내기)으로 넘어갈 수 있다

#### Acceptance Criteria

- **Scenario:** 합류 대기 화면에서 인원 불일치 사유 인라인 표시
- **Given:** 호스트가 합류 대기 화면에 있다
- **and Given:** 시나리오 캐릭터 수가 정수 C로 선언되어 있다
- **and Given:** 현재 합류자 수가 J다 (J ≠ C)
- **When:** 합류자 목록이 갱신된다
- **Then:** *"게임 시작"* 컨트롤이 비활성된 상태에서 그 인접 영역에 *"X명 더 필요"* (J < C 시 X = C − J) 또는 *"X명 초과 — 누군가 나가야 합니다"* (J > C 시 X = J − C)가 인라인으로 표시되고, J = C가 되는 즉시 사유 라벨이 사라지며 *"게임 시작"* 컨트롤이 활성화된다 (호스트 화면 한정 표시)
- **and Then (이탈 메커니즘 — J > C 회복):** 게스트 단말에는 합류 대기 화면 우상단(또는 명확한 자리)에 항상 *"나가기"* 컨트롤이 노출된다. 게스트가 *"나가기"*를 탭하면 본인 합류가 즉시 취소되어 호스트·다른 게스트 화면의 합류자 목록에서 닉네임이 사라지고 J가 1 감소한다. **호스트가 게스트를 *"내보내기"*로 강제 추방하는 컨트롤은 도입하지 않는다 — Host 비대칭 가드(§6) 준수 + 친구 그룹의 사회 마찰 회피.** 인원 초과 회복은 *그룹이 대면으로 합의해 한 명이 자발 이탈*하는 방식으로 처리
- **and Then (NB4 — 이탈 후 재합류):** 합류 대기(`session_state == lobby`) 단계에서 *"나가기"*로 이탈한 게스트가 마음을 바꿔 다시 합류하려 하면, **같은 초대 번호 + 같은 닉네임으로 새 합류 시도**가 가능하다 (이전 슬롯이 삭제되었으므로 *재합류*가 아니라 *새 합류*로 처리). 인원 J가 다시 1 증가하며 J = C가 되면 *"게임 시작"*이 활성화된다. **세션이 이미 시작된 후(`session_state == in_progress`)는 새 합류 자체가 차단되므로(E1-02b NB1) 이탈 후 재합류 불가** — 이탈 결정은 *게임 시작 전*에만 되돌릴 수 있다는 점이 *"나가기"* 컨트롤 인접 영역에 작은 안내 문구로 표시되어야 함
- **and Then (AB2 — 게임 중 이탈 비도입):** *"나가기"* 컨트롤은 **`session_state == lobby` 한정으로만 노출**되며, `in_progress` 진입 후에는 표시되지 않는다. 게임 중 이탈하고 싶은 플레이어는 *앱 강제 종료*만 가능하며, 이는 E1-02b의 *오프라인 상태*로 처리되어 본인 슬롯·캐릭터·아이템 ACL은 그대로 보존된다. **슬롯이 명시적으로 *"비워지는"* 분기는 도입하지 않음** — 근거: (1) 캐릭터 자동 배정과 시나리오 메타가 *J = C* 가정으로 작성되었으므로 슬롯 해제는 시나리오 정합성을 깸, (2) 친한 친구 그룹 페르소나에서 *중도 이탈*은 드물고 발생 시에도 친구들이 대면으로 *"잠깐 자리 비웠다"*로 자연 처리, (3) NF6의 호스트 강제 진행이 9-B에서 *오프라인 미응답자*를 처리하므로 세션은 끝까지 진행 가능

### User Story E1-04

- **Summary:** 캐릭터가 자동 배정되고 개인 정보가 본인에게만 도착한다

#### Use Case

- **As a** 플레이어
- **I want to** 단계 2에서 내 캐릭터와 비밀·동기 같은 개인 정보를 내 화면에서만 받고
- **so that** 옆 사람의 화면을 훔쳐보지 않으면 내 비밀이 보호된다는 걸 신뢰하고 몰입할 수 있다

#### Acceptance Criteria

- **Scenario:** 단계 2에서 캐릭터 자동 배정 + 개인 정보 1대1 전달
- **Given:** 단계 1이 끝났다
- **and Given:** 합류 인원 = 시나리오 캐릭터 수
- **When:** 엔진이 단계 2로 전환한다
- **Then:** 각 플레이어 단말의 본인 카드에 모든 필드(이름·직업·배경·동기·알리바이·비밀·관계 + 시나리오 저자 커스텀 필드)가 노출되고, 다른 캐릭터의 어떤 필드도 자동 동기되어 노출되지 않는다 (이름·직업처럼 공개되어야 할 정보는 시나리오 저자가 단계 1 도입 텍스트나 단계 2 캐릭터 소개 멘트로 직접 풀어 쓴다)

### User Story E1-04b

- **Summary:** 단계 3 규칙 공지가 인앱 튜토리얼로 대체된다

#### Use Case

- **As a** 플레이어
- **I want to** 단계 3에서 규칙을 호스트 1인의 낭독으로 듣는 대신 내 단말의 인앱 튜토리얼로 받고
- **so that** "지금 뭘 해도 되는지"를 다른 사람에게 묻지 않고 진행할 수 있고, 규칙 미숙지로 인한 초반 이탈을 줄인다

#### Acceptance Criteria

- **Scenario:** 단계 3 인앱 튜토리얼 (고정 문구) + 모든 합류자 통과 시 L1 전환
- **Given:** 단계 2가 종료되었다
- **When:** 엔진이 단계 3에 진입한다

### User Story E1-05

- **Summary:** 라운드 시작 시 라운드별 프롬프트와 타이머가 자동으로 켜진다

#### Use Case

- **As a** 플레이어

#### Acceptance Criteria

- **Scenario:** 루프 라운드 진입 시 프롬프트 + 타이머 자동 노출
- **Given:** 시나리오 메타가 총 라운드 수 N(MVP는 고정 횟수)과 각 라운드별 프롬프트·제한 시간을 선언한다
- **and Given:** 직전 라운드가 종료되었거나 단계 3이 종료되어 루프 첫 진입 시점이다

- **Then:** 모든 단말에 라운드 k 프롬프트 + 카운트다운 타이머가 동시에 표시되고 시간 경고 임계점에서 시각/햅틱 알림이 울린다

- **and Then:** 라운드 꼬리표(라운드 k)가 자동 부착되어 라운드 경계 도달 시 다음 라운드의 `common_hint`(선언된 경우)로 자동 교체된다 — 이전 라운드 힌트는 *카드 라운드 목표 자동 교체*(E2-02)와 동일하게 화면에서 사라지며 회상 컨트롤은 후속

### User Story E1-10

- **Summary:** 라운드 진입 시 회전 턴 순서대로 각자 30초 안에 후보 장소 1곳을 선택해 점유하고 그 장소의 단서를 받는다

- **As a** 플레이어
- **I want to** 새 라운드가 시작될 때 회전 턴 순서로 후보 장소에서 한 곳을 골라 조사하고 그 장소의 단서를 받고

#### Acceptance Criteria

- **Scenario:** 세션 시작 시 `turn_order` 셔플 — 시나리오 메타게임 스포일러 차단

- **Given:** 플레이어 A의 차례가 진행 중이며 후보 장소 X가 *"남은 후보"* 상태다
- **When:** A가 30초 안에 X를 탭하여 선택을 확정한다
- **Then:** X는 라운드 k 동안 A가 점유한 상태로 잠기고, 모든 단말에서 X 카드가 *"A 조사 중"* 점유자 닉네임으로 비활성 표시되며, X에 `origin_location_id == X`인 아이템(들)이 A의 단말 *"소유 아이템"* 섹션에 도착한다 (= 기존 Item ACL 메커니즘 그대로 재사용, 새 ACL 규칙 도입 없음). 라운드 경계 도달 시 점유는 자동 해제되어 다음 라운드의 `location_pool`은 다시 모든 장소가 후보로 노출

- **Scenario:** 시간 초과 — 남은 후보 중 랜덤 자동 선택
- **Given:** 플레이어 B의 차례에 30초 카운트다운이 진행 중이다
- **and Given:** B가 30초 안에 어떤 후보 장소도 탭하지 않았다
- **When:** 30초가 만료된다
- **Then:** 엔진이 *남은 후보 장소 중 1곳*을 무작위로 선택해 B에게 자동 점유 + 단서 도착 처리하고, 그 결과를 모든 단말에 동일한 *"X 조사 중 (자동 선택)"* 형태로 표시한다 (*"건너뛰기·미선택"* 옵션은 제공되지 않음 — 모든 플레이어가 매 라운드 단서 1개 보장)

- **Scenario:** 다음 차례 자동 진행
- **Given:** 라운드 k의 i번째 차례가 선택 확정 또는 시간 초과 자동 선택으로 종료되었다
- **When:** 점유 처리가 완료된다
- **Then:** 엔진이 즉시 다음 차례(`i + 1`)로 자동 전환하고, 라운드의 모든 캐릭터가 점유 처리를 완료하면 L2 단계가 종료되며 라운드의 나머지 진행(L1 토론·아이템 교환·밀담 등 A4.3~A4.5)이 활성화된다

### User Story E1-11

#### Use Case

### User Story E1-13

- **Summary:** 미션 자가 체크 결과가 판정 없이 그대로 저장된다

#### Use Case

- **As a** 플레이어
- **I want to** 단계 9-B에서 본인 미션 달성 여부를 ✓/✗로 직접 표시하고
- **so that** 앱이 옳고 그름을 판단하지 않고도 "내 이번 판은 어땠는지"가 종료 화면에 한 줄 요약으로 남는다

- **and Then (호스트 강제 진행 — 세션 미종료 회피):** 단계 9-B 진입 후 **첫 *"체크 완료"* 신호 수집 시점부터 3분 경과**해도 모든 플레이어 완료가 모이지 않으면, 호스트 단말에 *"강제 진행"* 컨트롤이 노출된다. 호스트가 탭하면 미완료 플레이어의 9-B 상태가 *"미응답"*으로 기록되고 (저장 형식: `mission_check = null`) 9-C 진입 트리거가 즉시 발동한다. 본 비대칭은 PRD §6 *"신규 모듈은 Host 비대칭을 늘리지 않을 것"* 가드의 **명시적 예외** — 세션 미종료(전원이 끝을 못 보는) 위험이 추상적 비대칭 증가보다 훨씬 큰 손실이라는 트레이드오프. 자동 타임아웃 (호스트 개입 없이 시간만으로 진행)은 도입하지 않음 — 호스트가 *"이대로 진행해도 되는지"*를 친구들 분위기 보고 판단하는 인간 결정이 자동 시간 임계점보다 자연스럽다
- **and Then (NB3 — 호스트가 미완료자에 포함 + 오프라인일 때 권한 일시 분배):** 강제 진행 노출 시점(첫 완료 후 3분 경과)에 **호스트 본인이 9-B 미완료자이고 동시에 오프라인 상태**(예: 호스트 단말 배터리 끊김)이면, *"강제 진행"* 컨트롤이 호스트가 아닌 **모든 합류자 단말에 동시 노출**되며 누구든 1명이 탭하면 강제 진행이 발동한다. 본 분기는 PRD §6 가드의 *"세션 진행 보장"* 예외와 §8 Q20 *"인계 없음"* 디폴트 사이의 충돌(NB3)을 해결하기 위한 좁은 인계 — *호스트 본인의 미완료가 직접적 차단 원인일 때 그 한 액션에 한해서만* 권한이 분배되며, 다른 호스트 액션(예: A2 시나리오 선택·시작)에는 인계되지 않음. 호스트가 재합류(E1-02b)하면 즉시 일반 호스트-only 모드로 복귀

### User Story E2-04

- **Summary:** 카드 안에서 "내가 가진 단서"와 "접근권만 가진 단서"가 분리되어 보인다

#### Use Case

- **As a** 플레이어
- **I want to** 내 카드의 아이템 영역에서 "내 소유"와 "접근권 보유"가 따로 묶여 보이고 각 단서에 발견 장소 라벨이 붙어 있고
- **so that** 누구에게 무엇을 건넬 수 있는지·어느 장소에서 나온 단서인지를 한눈에 판단할 수 있다

#### Acceptance Criteria

- **Scenario:** 두 섹션 분리 + 장소 라벨 일관 노출
- **Given:** 플레이어가 1개 이상의 단서를 소유하거나 접근권으로 보유한다
- **When:** 플레이어가 카드 아이템 영역을 연다
- **Then:** "소유 아이템"과 "접근권 보유 아이템" 두 섹션이 시각적으로 분리되고, `origin_location_id`가 매핑된 단서에는 [발견 장소 아이콘 + 이름]이 표시되며 (미매핑 단서는 장소 라벨 없이 노출), 라벨이 표시되는 단서는 E2-05의 동일한 [아이콘 + 이름] 양식을 그대로 따른다

### User Story E2-05

- **Summary:** L-Vis 1 — 장소 라벨이 모든 화면에서 일관된다

#### Use Case

- **As a** 플레이어
- **I want to** 라운드 진입 카드·알리바이 라벨·단서 발견 장소 라벨이 모두 같은 [아이콘 + 이름 + 1줄 분위기] 조합으로 일관되고
- **so that** "그 옥상 정원이 그 옥상 정원이 맞나?"를 의심하지 않고 알리바이 교차 검증을 머릿속에서 곧장 수행할 수 있다

#### Acceptance Criteria

- **Scenario:** L-Vis 1 일관 노출 + 아이콘 fallback
- **Given:** 시나리오 메타에 `Location.name`·`description`이 정의되어 있다
- **and Given:** `Location.icon`은 시나리오 저자가 선택한 이모지/아이콘 키 또는 미선언 상태다
- **When:** 플레이어가 라운드 진입 카드, 캐릭터 카드의 알리바이 라벨, 단서 카드의 발견 장소 라벨을 각각 본다
- **Then:** 세 위치 모두 동일한 아이콘 + 이름이 같은 시각 양식으로 노출되며, `icon` 미선언 시에는 세 위치 모두 동일한 기본 아이콘 `📍`가 일관되게 적용된다

### User Story E2-09

- **Summary:** "누가 누구와 밀담 중"이 전체 화면 상단 배너에 보인다

#### Use Case

- **As a** 플레이어
- **I want to** 밀담이 진행 중일 때 그 사실 자체가 전체 단말 상단 배너에 떠 있는 것을 보고
- **so that** "지금 둘이 따로 얘기하고 있구나"가 자연스럽게 게임 정보가 되어 추리 압박이 발생한다

#### Acceptance Criteria

- **Scenario:** 밀담 상태 배너 — 전원 노출, 한 쌍 한정
- **Given:** 시나리오에서 밀담이 허용되어 있고 한 쌍이 진행 중이다 (MVP는 동시 한 쌍만)
- **When:** 플레이어가 어떤 화면이든 본다
- **Then:** 모든 단말 상단에 "A, B 밀담 중" 배너(참여자를 쉼표로 나열)가 표시되며, 밀담 종료 시점에 해당 배너는 즉시 사라진다

### User Story E2-10

- **Summary:** 시나리오 카탈로그가 단일 카드 + "세션 만들기" 버튼만 노출한다

#### Use Case

- **As a** 호스트
- **I want to** 카탈로그에서 단일 시나리오 카드(제목·아이콘·인원·예상 시간·요약)와 *"세션 만들기"* 버튼만 보고
- **so that** 출시 시점 1편 상태에서 선택 마찰 없이 즉시 다음 단계로 넘어갈 수 있다

#### Acceptance Criteria

- **Scenario:** 단일 카드 카탈로그 — MVP 1편 가정
- **Given:** 카탈로그에 노출 가능한 시나리오가 1편 존재한다
- **When:** 호스트가 카탈로그 화면에 진입한다
- **Then:** 시나리오 카드에 [제목·아이콘·인원·예상 시간·요약]만 노출되고 *"세션 만들기"* 버튼이 함께 표시되며 (단계 1 전환 트리거인 *"게임 시작"*(E1-03)과 명시적으로 분리된 라벨), 태그 필터·소트·랜덤 버튼·다편 그리드는 본 화면에 노출되지 않는다 (시나리오 풀 확장 시 후속)

### User Story E2-11

- **Summary:** 포스트 엔딩 설문이 인라인 카드로 동거하고 플랫폼·작품 점수를 분리해서 받는다

#### Use Case

- **As a** 플레이어
- **I want to** 종료 화면에서 모달 팝업이 아닌 인라인 카드로 설문을 받고 한 화면에서 플랫폼 점수와 작품 점수를 별도 슬라이더로 응답하고 자유 텍스트는 한 칸에 적고 "응답"·"건너뛰기" 두 버튼이 시각적으로 동등해 보이고
- **so that** "플랫폼은 좋은데 시나리오는 별로" 같은 이중 평가를 분리해서 남길 수 있고, 거절이 어렵게 느껴지는 압박 없이 자연스럽게 응답하거나 빠져나갈 수 있다

#### Acceptance Criteria

- **Scenario:** 인라인 카드 + 두 차원 점수 동거 + 자유 텍스트 한 칸 + 동일 시각 가중 + 미응답 비차단
- **Given:** 단계 10이 종료되었다
- **When:** 종료 화면이 렌더링된다
- **Then:** 설문은 모달이 아닌 인라인 카드로 종료 화면에 동거하고, 1번 문항 영역에 플랫폼 점수 슬라이더와 작품 점수 슬라이더(둘 다 플랫폼 고정 문구) 2개가 한 화면에 노출되며 (각각 독립 응답·미응답 허용), 2번 영역에 자유 텍스트 한 칸(80자)이 노출되고, "응답하기"·"건너뛰기" 두 컨트롤이 동일한 시각 가중(크기·색·위치 우선순위)으로 노출되며, 둘 중 무엇을 눌러도 다음 화면(세션 종료) 진입이 막히지 않는다
- **and Then (카드 dismiss 트리거):** *"응답하기"* 또는 *"건너뛰기"*를 탭한 시점에 설문 카드가 즉시 dismiss되어 동일 종료 화면 위에서 사라지고, 그 자리에 E2-12의 *"수고했어요" + 미션 한 줄 요약*이 단독 노출된다 (별도 페이지 전환·로딩 인디케이터 없음 — 카드 동거 → 카드 dismiss는 같은 화면 위의 두 상태). 응답하기 탭 시 자동 dismiss 외에 별도 *"제출"* 액션은 없으며, "응답하기" 탭 자체가 응답 확정 + dismiss를 동시에 수행

### User Story E2-12

- **Summary:** 세션 종료 화면이 "수고했어요" 메시지와 본인 미션 한 줄 요약을 표시한다

#### Use Case

- **As a** 플레이어
- **I want to** 설문 카드(또는 건너뛰기) 다음에 종료 화면을 보고
- **so that** "이 판이 끝났구나"라는 마침이 자연스럽게 오고, 내가 직전에 ✓/✗로 표시한 미션 결과가 한 줄로 정리되어 친구들과 즉석에서 짧게 회상할 수 있다

#### Acceptance Criteria

- **Scenario:** 종료 화면 — "수고했어요" + 본인 미션 한 줄 요약 + 외부 공유 없음
- **Given:** 본인이 참여한 세션이 종료되어 설문 카드 다음 화면이 렌더링된다
- **When:** 플레이어가 종료 화면을 본다
- **Then:** "수고했어요" 메시지와 본인 미션·자가 체크 결과(✓/✗) 한 줄 요약이 표시되며, 별도 회상 화면(아이템 행위 이력 등)·외부 공유·다운로드 컨트롤은 노출되지 않는다 (Keepsake 회상 화면은 MVP 밖)
